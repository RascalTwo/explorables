LiteLLMKey Operator — the always-on key vendor

A LiteLLMKey CR in etcd, reconciled continuously by two operators (Ansible & Java) against the same live gateway. Same contract as the one-shot keys-sync / tf-apply engines — promoted to a self-healing controller. Drive it live.

🗺️ Anatomy of one LiteLLMKey — where everything lives

Boxes inside boxes = lives inside. CR the desired-state object you author · Secret where the real key lands for pods to mount · gateway key the actual credential, held outside the cluster. The operator's one job: keep the gateway key matching the CR — forever.

What only an always-on operator does

🔁 Continuous reconcile
Event-driven + a ~30s resync. The desired state is a native object; the loop never stops — unlike a one-shot apply.
🩹 Self-healing drift
Tamper a key out-of-band → the next resync reverts it automatically. No human, no re-run.
⏱️ Autonomous rotation
Auto-rotate sets rotationIntervalSeconds; the token rotates on a clock with no spec change. Terraform/cron can't.
🗑️ Finalizer delete-choice
Del soft = block & retain (restore reactivates the SAME token); Del hard = gone. Terraform only hard-destroys.
Both engines share one CRD & one contract — only the reconcile “brain” differs (Ansible role vs Java/JOSDK). The same key per engine stays live at once via distinct aliases.
