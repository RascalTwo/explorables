## 0. The standard itself (agentskills.io)

- **Origin:** Anthropic built the format and published it as an open standard. 🟢 https://agentskills.io/ `originally developed by`. It was published as an open standard on 2025-12-18 🟡 (search summary of claude.com blog). Skills first launched in Claude on 2025-10-16. 🟢 https://claude.com/blog/skills
- **Layout:** a skill is a folder `skill-name/` containing `SKILL.md` (required) plus optional `scripts/`, `references/`, and `assets/`. 🟢 https://agentskills.io/specification `Directory structure`
- **Frontmatter** (verbatim table): 🟢 https://agentskills.io/specification `Frontmatter`

| Field | Req | Constraint |
|---|---|---|
| `name` | Yes | 1–64 chars. Lowercase a-z, 0-9, and hyphens only. No leading, trailing, or doubled hyphen (`--`). **Must match the parent directory name** |
| `description` | Yes | 1–1024 chars. Should say what the skill does **and when to use it** |
| `license` | No | License name or a bundled license file |
| `compatibility` | No | 1–500 chars. Environment requirements (product, packages, network) |
| `metadata` | No | Map of string to string |
| `allowed-tools` | No | Space-separated pre-approved tools. **Experimental**; support varies by host |

- **Progressive disclosure:** about 100 tokens of metadata per skill are loaded at startup. The SKILL.md body should stay under 5000 tokens, **under 500 lines**, and is loaded on activation. Resources are loaded only when needed. 🟢 same page `Progressive disclosure`
- **File references:** use relative paths from the skill root and keep references **one level deep**. 🟢 same page `File references`
- **Validation:** `skills-ref validate ./my-skill`, from https://github.com/agentskills/agentskills/tree/main/skills-ref 🟢 `Validation`. `gh skill publish` (gh ≥ 2.90.0) also validates against the spec, and `--fix` auto-corrects metadata. 🟢 https://github.blog/changelog/2026-04-16-manage-agent-skills-with-github-cli/ `publish`

### Portable-skill checklist (synthesised from the spec plus the strictest platform rules below)
1. Folder name = `name`: lowercase-hyphen, ≤64 chars, no `--`. Avoid `anthropic` or `claude` in the name, because the Claude API and claude.ai reject them. 🟢 platform.claude.com overview `reserved words`
2. `description` in **third person**, saying what the skill does and "Use when …", with trigger keywords **front-loaded**. Codex shortens descriptions when many skills are installed, and Claude Code truncates description plus `when_to_use` at 1,536 chars. **Keep it ≤200 chars if the skill must upload to claude.ai**: the help center states a 200-char maximum, which conflicts with the 1024 in the spec (see Conflicts). No XML tags anywhere.
3. Put **only spec fields** in the frontmatter (`name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools`). Claude Code documents that non-spec keys cause a **hard upload error** on claude.ai and the Skills API: `Unexpected key(s) in SKILL.md frontmatter`. 🟢 code.claude.com/docs/en/skills `Unexpected key`. Put host-specific extras in sidecar files instead, for example Codex's `agents/openai.yaml`.
4. Keep the SKILL.md body under 500 lines. Move detail into `references/*.md` linked directly from SKILL.md, and give long reference files a table of contents.
5. Use relative paths with forward slashes only. Don't rely on `${CLAUDE_SKILL_DIR}`, `` !`cmd` `` injection, `$ARGUMENTS`, or `@file` references, because these are Claude Code-only and reach other hosts as literal text.
6. Scripts: self-contained, clear error messages, dependencies listed in SKILL.md, and a stdlib-only fallback where possible. Assume **no network** (Claude API, Gemini app) and **no runtime package install** (Claude API).
7. Don't hard-code secrets. Don't make one skill call another skill by name, since claude.ai says skills can't reference each other.
8. Name MCP tools fully qualified (`Server:tool`) and state in `compatibility` that the MCP server is required.
9. Package the ZIP with the **skill folder at the zip root** (`my-skill.zip → my-skill/SKILL.md`).
10. Test the trigger in a fresh session on each target host. Descriptions compete for a budget: 2% of context or 8,000 chars in Codex, 1,536 chars per skill in Claude Code.

## 1. Claude Code (CLI, IDE extensions, desktop, web)

- **Support:** Yes. States that it "follows the Agent Skills open standard". 🟢 https://code.claude.com/docs/en/skills `Agent Skills open standard`
- **User steps**
  - Locations, highest precedence first: Enterprise (managed-settings dir) > Personal `~/.claude/skills/<name>/SKILL.md` > Project `.claude/skills/<name>/SKILL.md` > nested `<subdir>/.claude/skills/`. Plugin skills are namespaced `/plugin:skill`. `--add-dir` dirs are also read. 🟢 same page `Where skills live`
  - claude.ai account skills **sync down** to `~/.claude/skills/synced/` (needs v2.1.273+ and claude.ai login; turn off with `syncClaudeAiSkills: false`). Invoke them as `/anthropic-skills:<name>` or the short name. Sync is **download-only**. 🟢 same page `synced`
  - Invocation: automatic by `description`/`when_to_use`, or `/skill-name`. The directory name is the command, except for plugin skills. Up to 6 skills can be stacked in one message. 🟢 `Stacking`
  - Live reload for existing skills dirs. Creating a new top-level skills dir needs a restart. `/skills` lists them, `/skill-doctor` (v2.1.252+) shows context cost. 🟢
  - Scripts run on the user's machine with **full network access**. Global package installs are discouraged. 🟢 https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview `Full network access`
- **Author requirements / extensions:** All fields are optional in Claude Code: `name` defaults to the dir name and `description` defaults to the first paragraph. Claude Code-only fields: `when_to_use, argument-hint, arguments, disable-model-invocation, user-invocable, disallowed-tools, model, effort, context: fork, agent, background, hooks, paths, shell`. Body features: `$ARGUMENTS`, `$0`, `${CLAUDE_SKILL_DIR}`, `` !`cmd` `` dynamic injection. **Invalid YAML fails silently**: the skill loads with no fields. Unknown keys are ignored. 🟢 `Frontmatter reference`
- **Gotchas:** description plus `when_to_use` are truncated at 1,536 chars. Invoked skill bodies stay in context and survive compaction up to 5k tokens per skill / 25k total. Don't name a folder `synced`. Project skills' `allowed-tools` pre-approve tools **without workspace-trust gating**, so review skills in untrusted repos. 🟢

## 2. Claude Agent SDK (Python / TypeScript)

- **Support:** Yes, filesystem-only. "The SDK doesn't provide a programmatic API for registering them." 🟢 https://code.claude.com/docs/en/agent-sdk/skills `programmatic API`
- **User steps:** put skills in `.claude/skills/` or `~/.claude/skills/`. The default `query()` loads the user and project sources. If you set `settingSources` / `setting_sources` explicitly, include `"user"` and `"project"`. The `skills` option takes `"all"`, a list of names, or `[]`. If you pass an explicit `tools` list, include `"Skill"`. Loading from an arbitrary path goes through the `plugins` option. `/name` in the prompt dispatches a skill even when it isn't allowlisted. 🟢 same page `settingSources`, `Dispatch commands by name`
- **Gotchas:** wildcards in `skills` are rejected (`Invalid skill name "docs:*"`). The skill must sit at or above `cwd` within the repo. `allowed-tools` frontmatter does apply in SDK sessions. 🟢

## 3. claude.ai (web, desktop; Microsoft 365 add-ins)

- **Support:** Yes (custom skills since 2025-10-16 🟢 claude.com/blog/skills).
- **User steps:** Customize > Skills > **+** > **+ Create skill** > **Upload a skill**, then upload a ZIP. Code execution must be enabled. On Team/Enterprise, an owner must enable "Code execution and file creation" **and** "Skills" under Organization settings > Plugins & skills. 🟢 https://support.claude.com/en/articles/12512180-use-skills-in-claude `Upload a skill`
  - Invocation: automatic, or ask explicitly ("Use my brand guidelines skill"). The `/` picker is documented for the M365 add-ins; no chat `/` command is documented for web. 🟢/🟡 same page
  - Sharing: Team/Enterprise admins can provision org-wide (Organization settings > Plugins & skills > Add), users can share with people or groups (view-only, off until enabled), and groups can be assigned via plugins. 🟢 https://support.claude.com/en/articles/13119606-provision-and-manage-skills-for-your-organization `provisioned to all users`
  - Network: "full, partial, or no network access" depending on user/admin settings. Can install from npm and PyPI and pull from GitHub. 🟢 platform overview `Varying network access`; best-practices `Package dependencies`
  - Enterprise can turn on **Skill content scanning** for uploads. 🟢 platform overview `Skill content scanning`
- **Author requirements (help center, updated 2026-07-22):** "name … (64 characters maximum)", "description … (**200 characters maximum**)" (verbatim). Optional `dependencies` field. The ZIP must have the skill folder as root. The file is called `skill.md` in the help text. Scripts can be Python or JS. 🟢 https://support.claude.com/en/articles/12512198-how-to-create-custom-skills `200 characters maximum`
  - Upload errors listed: ZIP exceeds size limits (the limit itself is **not stated**), folder name ≠ skill name, missing skill.md, invalid characters. 🟢 12512180 `size limits`
  - Non-spec frontmatter keys produce a hard error. `!` injection, `@` refs, and `${CLAUDE_*}` don't work. 🟢 code.claude.com/docs/en/skills `Unexpected key`
- **Gotchas:** custom skills **do not sync across surfaces** (claude.ai ↔ API ↔ Code), except that claude.ai → Claude Code sync now exists (see §1). 🟢 platform overview `do not sync across surfaces`. **Mobile:** not documented either way 🔴.

## 4. Claude API (Messages API; also Claude Platform on AWS, Microsoft Foundry)

- **Support:** Yes. Upload with `POST /v1/skills` (zip or multipart; SDK `client.skills.create(files=files_from_dir(...))`), version with `POST /v1/skills/{id}/versions` (the full file set each time, and `name` must match). 🟢 https://platform.claude.com/docs/en/build-with-claude/skills-guide `Creating a Skill`
- **Use:** `container: {skills: [{type: "anthropic"|"custom", skill_id, version}]}` **plus the code execution tool** (`code_execution_20250825`). Limits are "up to **20** Skills for each request" and "Total upload size must be under **30 MB** (uncompressed)" (verbatim). Get output files through the Files API. Handle `pause_turn`. 🟢 same page `up to 20`, `30 MB`
- **Runtime:** "No network access", "No runtime package installation", pre-installed packages only. 🟢 overview `No network access`
- **Scope:** workspace-wide, so all keys in the workspace can use every custom skill. Use separate workspaces per tenant. 🟢 skills-guide `workspace`
- **Gotchas:** `name` can't contain "anthropic" or "claude", and name/description can't contain XML tags. Not ZDR-eligible. On Foundry, requires a "Hosted on Anthropic" deployment. 🟢 overview `reserved words`, `ZDR`. The page as fetched shows **no `anthropic-beta` header** requirement. Older docs required betas, so recheck before publishing 🟡.
- Managed Agents also has a skills page (https://platform.claude.com/docs/en/managed-agents/skills). I did not open it 🔴.

## 5. OpenAI Codex (CLI, IDE extension, Codex in the ChatGPT desktop app, Codex web)

- **Support:** Yes. "Skills build on the open agent skills standard." 🟢 https://learn.chatgpt.com/docs/build-skills (developers.openai.com/codex/skills 308-redirects here) `open agent skills standard`
- **Locations** (verbatim table): REPO `$CWD/.agents/skills`, `$CWD/../.agents/skills`, `$REPO_ROOT/.agents/skills`; USER `$HOME/.agents/skills`; ADMIN `/etc/codex/skills`; SYSTEM bundled (skill-creator, skill-installer). Symlinks are followed. Same-name skills are **not merged** and both show. 🟢 `Where Codex loads local skills`. Note: `~/.codex/skills` is **not listed** on the current page (older docs used it 🔴).
- **Invocation:** implicit by description, or explicit with `$skill-name` or `/skills` (CLI/IDE). The ChatGPT side uses `@`. 🟢 `Explicit invocation`
- **Install / disable:** `$skill-installer <name>` installs curated skills from openai/skills. Disable with `[[skills.config]] path=… enabled=false` in `~/.codex/config.toml`, then restart. 🟢 `skill-installer`, `skills.config`
- **Author extensions:** optional `agents/openai.yaml` with `interface` (display_name, short_description, icons, brand_color, default_prompt), `policy.allow_implicit_invocation` (default true), and `dependencies.tools` (MCP servers). Other hosts ignore it because it's a separate file. 🟢 `Optional metadata`
- **Budget:** "at most 2% of the model's context window, or 8,000 characters". Descriptions are shortened first, and some skills may be omitted with a warning. 🟢 `8,000 characters`
- **Plans:** "Codex is included across ChatGPT plans, including Free and Go." 🟢 https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan `including Free and Go` (read in Chrome; WebFetch got 403)
- **Distribution:** OpenAI recommends plugins for sharing. Plugins bundle skills, MCP, and apps. 🟢 `Distribute skills with plugins`
- **Extra:** Record & Replay in the ChatGPT desktop app (macOS, Codex mode) turns a demonstration into a skill. Not available in the EU, CH, or UK. 🟢 help 11369540 `Record & Replay`

## 6. ChatGPT (chat on web / desktop / mobile)

- **Support:** Yes, but **only for eligible Business, Enterprise, Healthcare, and Edu users**. 🟢 https://help.openai.com/en/articles/20001066-skills-in-chatgpt `eligible ChatGPT Business` (read in Chrome, updated about 2026-08-30)
- **Surfaces:** "Standalone skills are available in the ChatGPT desktop app, Codex CLI, and IDE extension. Skills bundled in plugins are also available in Chat and Work across ChatGPT on the web, desktop, and mobile." 🟢 learn.chatgpt.com/docs/build-skills `Standalone skills`
- **User steps:** Sidebar > **Plugins** > **Skills** tab > **Create** > **Upload from your computer**. Other options: Create with chat (uses the bundled `skill-creator`), Create with editor, or install one shared with you. Invoke with `@` or automatically. Uploads are **scanned** and can come back Available, Needs Review, or Blocked. 🟢 20001066 `Upload from your computer`, `Needs Review`
- **Admin:** Enterprise/Edu roles control enable skills, uploading, sharing, publishing, and installing for others. There's an admin Skills page with 30-day invocation counts. 🟢 same page
- **Author:** the upload format (zip vs folder) and size limits are **not stated** on the help page 🔴. Use the OpenAI API limits below as a proxy 🟡.
- **Personal plans (Free/Go/Plus/Pro):** no standalone skills in chat per the eligibility sentence. Use Codex instead, or a plugin that bundles the skill (plugin install eligibility "depends on their plan…"). 🟢/🟡 help 11369540 `Plugins Directory is visible across ChatGPT plans`

## 7. OpenAI API (Responses API)

- `POST /v1/skills` (zip or multipart). Limits: **50 MB compressed, 25 MB uncompressed, 500 files per version**. SKILL.md is matched case-insensitively, and `name`/`description` must be in frontmatter. Used with the **shell tool**, either `environment.type="container_auto"` (hosted) or `"local"`. Versions via `default_version`/`latest_version`. Warns that skills combined with open network access are "high-risk". 🟢 https://developers.openai.com/cookbook/examples/skills_in_api `500 files` (a cookbook, not reference docs, so 🟡 on the exact numbers)

Current surfaces: cloud agent, code review, CLI, Copilot app, and agent mode in VS Code and JetBrains. 🟢 https://docs.github.com/en/copilot/concepts/agents/about-agent-skills `Copilot code review`

VS Code additionally reads `~/.claude/skills`. 🟢 https://code.visualstudio.com/docs/copilot/customization/agent-skills `Personal skills`
- **Invocation:** automatic, or `/skill-name`. CLI: `/skills list|info|reload|add`. 🟢
- **Install:** `gh skill install <owner/repo> [skill][@ver]`, `gh skill search`, `gh skill update`, and `--agent claude-code|cursor|codex|gemini` to target other hosts. Needs gh ≥ 2.90.0. 🟢 https://github.blog/changelog/2026-04-16-manage-agent-skills-with-github-cli/

- **Plans:** code review with skills + MCP went GA on 2026-07-29 for Pro, Pro+, Business, and Enterprise. 🟢 https://github.blog/changelog/2026-07-29-copilot-code-review-agent-skills-and-mcp-now-generally-available/. CLI is GA "for all Copilot subscribers" (2026-02-25). 🟢. Whether Copilot Free gets skills: 🔴 not stated.
- **Cloud agent:** no personal or org-level skills beyond the paths above are documented. Script runtime and firewall behaviour aren't documented on the skills page 🔴.

## 9. Cursor (editor + CLI; cloud agents)

- **Locations:** project `.agents/skills/`, `.cursor/skills/`; user `~/.agents/skills/`, `~/.cursor/skills/`; legacy `.claude/skills/`, `.codex/skills/` and their home equivalents. ## 10. Gemini CLI → Antigravity CLI / IDE

- **Gemini CLI:** Yes. Tiers, lowest to highest precedence: built-in < extension < user (`~/.gemini/skills/`, `~/.agents/skills/`) < workspace (`.gemini/skills/`, `.agents/skills/`). Within a tier, `.agents` wins. Activation goes through the `activate_skill` tool and shows a **consent prompt** with the directory it will access. Commands: `/skills list|enable|disable|reload|link`; `gemini skills install|uninstall|list --scope user|workspace`. Name must match the dir. 🟢 https://geminicli.com/docs/cli/skills/ and https://geminicli.com/docs/cli/creating-skills/
- **Sunset:** announced 2026-05-19. On **2026-06-18** Gemini CLI "stop[ped] serving requests for Google AI Pro and Ultra, as well as those using it free of charge". It stays available for Code Assist Standard/Enterprise. Skills, hooks, subagents, and extensions (now "Antigravity plugins") carry over to Antigravity CLI. 🟢 https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/
- **Antigravity (IDE + CLI):** workspace `.agents/skills/` (legacy `.agent/skills/`). Global: IDE `~/.gemini/config/skills/`, CLI `~/.gemini/antigravity-cli/skills/`, plugin skills `~/.gemini/antigravity-cli/plugins/<name>/skills/`. `name` is **optional** (defaults to the folder) and `description` is required. Auto-trigger or `/skill-name`. 🟢 https://antigravity.google/docs/skills/
- **Author note:** Antigravity's documented optional folders are `scripts/ examples/ resources/`, not the spec's `references/ assets/`. Harmless, but a naming divergence. 🟢

## 11. Gemini app (consumer) and Gemini Enterprise

- **Gemini app:** Yes. This is **not Gems**: skills live under "Spark". Path: gemini.google.com > Sidebar > Switch to Spark > Skills. Create with Gemini, from a template, manually, or by **uploading a SKILL.md or a .zip** with SKILL.md at the root. Name rule: lowercase-hyphen. **≤100 MB total**. Text and code file types only; PDF, DOCX, and images are rejected. "Scripts can't perform actions or requests on external websites." Invoked automatically or with `/`. Requirements: 18+, **personal** account, **Google AI Pro/Ultra**, Keep Activity on, not EEA/UK/CH/Nigeria. Works in the web app, the Mac app, and Spark in the mobile app; mobile allows only conversational edits. 🟢 https://support.google.com/gemini/answer/17094296 `100 MB`

"Skills support Python and Bash execution only." Admins can suspend, disable, or delete skills. Standard / Plus / PAYG editions can create; Frontline editions can only install. Page updated 2026-09-24. 🟢 https://docs.cloud.google.com/gemini/enterprise/docs/skills
- **Gems:** there's no evidence that Gems accept SKILL.md. Treat Gems as the "no-skill fallback" (paste the body into Gem instructions). 🔴

## 14. Fallback: AI with no skill support

- Paste the SKILL.md **body** into the chat, a custom-instructions field, or a Project/Gem. Attach `references/*` as knowledge files. Scripts only help if the host can run code and you upload them. Nothing is loaded progressively; everything sits in context all the time. (Reasoning, not a sourced fact.) 🔴
- **Custom GPTs are being retired.** New GPT creation is already off for Free, Go, Plus, and Pro. Retirement is planned for **2026-12-11** for affected Enterprise workspaces, with other plans "expected to follow the same timeline". OpenAI recommends migrating to Plugins. Knowledge limits while GPTs still exist: 20 files, 512 MB each. 🟢 https://help.openai.com/en/articles/8554397-creating-and-editing-gpts `retire custom GPTs` (read in Chrome)
- Claude Projects and Gemini Gems work as fallbacks, but I didn't research their current limits 🔴.
